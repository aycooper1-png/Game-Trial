Notes for any AI asked to work on this game

This page is the live game "Game Trial" (a remake and expansion of yclen's Map Factory prototype). If the owner gave you only this link, everything you need is reachable from here:

  • Source code (all changes are made here, branch main): https://github.com/aycooper1-png/Game-Trial
  • Full handoff notes, required reading before any change: https://aycooper1-png.github.io/Game-Trial/CLAUDE.md (the same file is CLAUDE.md in the repository)
  • Player-facing feature list: README.md in the repository
  • Pushing to main republishes this page automatically (GitHub Pages) within a minute or two.

The procedure the owner wants, every time

  1. For EVERY new message from the owner, re-read all the notes: CLAUDE.md fully (code layout, testing, publishing, the owner's words, and design decisions already made that must not be undone without asking), this block, README.md and tests/README.md. Say in your reply that you did. Then read the code each request touches. (Exception: a brief question that needs no change to the game, such as "what is the link?", needs no re-read and no questions: just answer.)
  2. Before writing any code, ask as many clarifying questions as possible and wait until ALL are answered. Then ask follow-up questions whenever an answer is still unclear, or seems illogical or harmful to the game. Reply with a plain restatement of each numbered item and as many numbered clarifying questions as are useful: scope (which units/buildings/worlds, computer nations too?, both multiplayer players?), numbers, edge cases, conflicts with earlier decisions, how it should look, the iPhone layout. Explain hard questions with examples and options. Then wait for the answers. If the owner says "explain this before acting", explain and wait.
  3. Build in stages; after each stage check the code (node --check game.js) and run the matching tests in tests/.
  4. Keep the notes (CLAUDE.md) up to date carefully and accurately as you go: after each stage and each answer from the owner, record what changed and what they decided (their numbers vs. yours), checked against the code. Wrong notes mislead the next AI. See section 9 of CLAUDE.md.
  5. One commit and push per request; bump the ?v=N cache tag in index.html; update README.md and CLAUDE.md.
  6. Report in plain language (the owner is not a programmer and plays mostly on an iPhone): what changed per item, what was and wasn't tested, side effects, and any numbers you chose.

Words that are easy to misread

  • "The AI" in a game request usually means the in-game AI (the central computer upgraded to C.A.I.S., which runs roads, building, trade or war for the player), sometimes the computer nations; rarely you. Ask if unclear.
  • "Territory" and "domain" are the same: one of the player's separate pieces of land, with its own stock.
  • "Porters" can mean all road haulers or only the first model; check the context.
  • "Second player" = the multiplayer guest; "main player" = the host. The second player must be able to do everything the host can, except creative mode.

If you cannot edit the repository or run code, say so at the start; you can still read the code and ask the questions.
